## Why Archive Instead of Update?

Planning guides are **point-in-time snapshots** created during sprint planning. They represent:

- Initial assumptions and plans
- Early architectural decisions
- Pre-implementation thinking

When implementation diverges from the plan (which is normal), we:

1. Keep the original planning doc as historical reference (archived)
2. Create a status report showing actual implementation (e.g., SPRINT2_STATUS.md)
3. Update JIRA with the real story status

**This prevents confusion** between what was planned vs. what was actually built.

---

## Best Practices

- ✅ Use JIRA as source of truth for story status
- ✅ Use `SPRINT{N}_STATUS.md` for implementation reality
- ✅ Archive outdated planning guides here
- ❌ Don't update planning guides during sprint execution
- ❌ Don't delete them (they provide historical context)
